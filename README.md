**Ход рассуждений:**

Итак, мой ход рассуждений был следующим: после ознакомления с заданием я сразу подумала про кастомные компоненты. Их можно описать как классы, а потом зарегистрировать через customElements.define(), чтобы использовать в HTML как обычные теги. Я уже изучала это самостоятельно на работе, но мне нужно было вспомнить синтаксис, поэтому я обратилась к статье, которую указала выше. Согласно ТЗ, у прогресс бара должен быть API для управления его состоянием. Я решила сделать три метода: один для задания значения, второй для включения/выключения анимации, третий для скрытия и показа компонента. Для первого метода как раз подошёл способ с CSS-переменной --progress-value, который я так же взяла из вышеуказанной статьи. От неё зависит длина синей дуги, поэтому, когда в input вводится число, оно передается в setValue() и переменная обновляется. С остальными двумя методами всё проще, то есть для анимации я добавляю или убираю соответствующий класс через toggle, а для скрытия меняю свойство hidden, и когда оно равно true, к прогресс бару применяется display: none.

В итоге получился переиспользуемый компонент, который так же можно использовать и как лоадер. Например, если у нас есть isLoading из Tanstack Query, то при его изменении можно вызвать progress.isAnimated(isLoading) и progress.isHidden(!isLoading). И пока идёт загрузка, компонент будет виден и будет вращаться. Когда загрузка закончится, он, соответственно, скроется.
